# Couponia Catalog — שלב 5.6

## מה השתנה

מחולל ההטבות יכול כעת לפרסם אפשרות רכישת שובר הכוללת קשר מפורש בין המועדון, מוצר השובר, מזהי החנויות, ערוץ המימוש והמחיר באגורות. האפליקציה יכולה להשתמש במידע הזה בחיפוש חנות. לא נוספו הצעות מדומות: `approved_offers.json` ו־`offer_rights_grants.json` נשארו ריקים, וכל מקורות ההטבות נשארו כבויים.

מועדון HOT התווסף כמקור נפרד מ־HTZone. הצהרת המשתמש על כרטיס HOT Visa, Mastercard או American Express מאפשרת לסנן הצעות רלוונטיות; היא אינה מוכיחה עמידה בדרישות המנפיק. לא אומתה הצעת HOT נוכחית עבור שופרסל שלי או שופרסל בעיר, ולכן לא פורסם שיוך כזה.

## תיקונים בעקבות הסקירה

- כיבוי מקור ברישום המקורות נאכף כעת גם כאשר קיים אישור שימוש תקף.
- תוקף ההצעה המפורסמת מוגבל גם לסיום הרשאת המקור, כדי שמטמון במכשיר לא ימשיך להציג אותה מעבר לכך.
- אורך השדות וסוגיהם תואמים לחוזה הקליטה של Android. הצעה עם שדה פסול מוחרגת מהפרסום; כתובת פגומה אינה מפילה את כל ההזנה.
- מספרים כספיים ברכישה הם מספרים שלמים באגורות. ערכים בוליאניים, מחרוזות, מחיר שאינו נמוך מהשווי וערכים לא סופיים נדחים.
- כפל מזהי הרשאות מזוהה גם כאשר אחת ההרשאות כבר פגה.
- שם עסק שמתנרמל לכמה עסקים קיימים דורש בירור, במקום יצירה אוטומטית של עסק נוסף.
- תאריכי אימות נבדקים כתאריכים אמיתיים, ולא רק כתבנית טקסט.
- ההשוואה לפרסום הקודם בודקת גם את מזהי המוצרים, העסקים והקשרים, לאחר אימות SHA-256. כך מחיקה קטנה של שיוך שנוסף בגרסה קודמת אינה נבלעת בסף הכמות של 10%. שינוי אמיתי בתנאי המנפיק עדיין דורש עדכון מתועד של נתוני ההשוואה/כללי המעבר; ההגנה אינה קביעה ששיוך תקף לנצח.
- כאשר הקטלוג עצמו לא השתנה, נשמר גם תאריך הפרסום שלו, אפילו אם פרסום הזנת ההטבות גורם להעלאת חבילת האתר.
- הוסרו ייבוא וקבועים שלא היו בשימוש; כללי התחום, המקורות והרכישה הופרדו ממנגנון הפרסום.

## חוזה רכישת שובר

הפורמט נשאר `schemaVersion: 1`; נוסף אובייקט אופציונלי בשם `purchase` להצעה מסוג `voucher_discount`.

| שדה | משמעות וכלל |
|---|---|
| `voucherCardId` | מזהה מוצר קיים ב־`cards.json`; עד 160 תווים |
| `merchantIds` | 1–100 מזהי עסקים קיימים, ללא כפילות |
| `redemptionChannel` | `in_store`, `online` או `both` |
| `membershipIds` | 1–20 מזהי חברות ידועים, ללא כפילות, המשויכים למקור ההצעה |
| `faceValueMinor` | שווי חיובי באגורות; מספר שלם, עד 1,000,000,000,000 |
| `priceMinor` | מחיר חיובי באגורות; מספר שלם הקטן מהשווי |
| `currency` | `ILS` |
| `purchaseUrl` | כתובת HTTPS במתחם הרשמי המאושר של מקור ההצעה; עד 500 תווים |
| `conditionsSummary` | תנאי רכישה ומימוש תמציתיים; 1–500 תווים |

מזהי החברות הנתמכים: `max-card`, `isracard-card`, `cal-card`, `amex-card`, `leumi-bonus`, `poalim-wonder`, `htzone-member`, `hot-visa`, `hot-mastercard`, `hot-amex`. חברות HOT אינה הופכת אוטומטית לחברות HTZone או לזכאות לכל הטבות ישראכרט.

לפרסום רכישה נדרש קובץ קטלוג v3 עם SHA-256 תקין, מוצר קיים, עסק קיים וקשר קיים **בין אותם מזהים בדיוק**, בסטטוס `listed`. נדרש גם ערוץ תואם. `both` בראיות תומך בחנות ובאינטרנט; `in_store` אינו מוכיח התאמה באינטרנט ולהפך. היקפים מותרים: `network`, `venue`, `single_brand_only`, וכן `online` כאשר הבקשה היא לאינטרנט בלבד. היקף לא ידוע או מוגבל לסניפים אינו מספיק להמלצה אוטומטית.

אין ירושה בין שם רשת לפורמט או סניף. מזהה של שופרסל אינו אישור למזהה נפרד של שופרסל שלי. שדות תיאור, מחיר או שם עסק אינם מחליפים ראיית מימוש.

דוגמאות מלאות קיימות רק ב־`tests/test_stage56_purchase.py` ומסומנות כנתוני בדיקה. אין להעתיק אותן לקובץ ההצעות לפרסום.

## פרסום ובדיקות

הרצת GitHub Actions נשארת `Build unified Israeli gift-card catalog`. שלב ההטבות מקבל כעת גם `--catalog-dir dist/v3`. התהליך אינו מעדכן תאריך בדיקה ידני אוטומטית, אינו מתחבר לחשבון מועדון ואינו מבצע רכישה.

פקודות בדיקה מקומיות משורש המאגר:

```bash
python -m unittest discover -s tests -v
python src/build.py --seed seed/catalog-v2.db --curated-file config/curated_issuer_facts.json --out dist/v3
python src/catalog_guard.py --seed seed/catalog-v2.db --catalog dist/v3/catalog.db
python -m src.publish_offers --catalog-dir dist/v3 --out dist/offers/v1
```

לאימות הגרסה נעשה שימוש ב־seed המקורי מהמאגר הציבורי, commit `e35892177a2bca54b7d0c469f9241fa76a8697f0`, ובקובצי העדכון הקודמים. לא נוצר seed חלופי מתוך קובצי האפליקציה. נתוני הקטלוג נשארו 108 מוצרים, 462 עסקים ו־648 שיוכים; שלב זה מתקן את ההתנהגות ואת חוזה ההטבות.

## גבולות הבדיקה

הבדיקות אינן מאמתות מחדש באתרי המנפיקים כל שיוך היסטורי. במאגר הנוכחי 627 מתוך 648 קשרים עדיין מסומנים בערוץ מימוש `unknown`; אלה אינם הופכים להמלצות רכישה אוטומטיות. נדרשת השלמה ידנית מבוססת מקור לפני שיוך לפורמט מסוים של סופר או לערוץ רכישה.

המנגנון הקיים עדיין בונה ומפרסם את הקטלוג ואת ההטבות באותו workflow. כשל בבניית הקטלוג מונע גם פרסום הזנת ההטבות באותה ריצה. האפליקציה מסננת הצעות שפג תוקפן או שלא נבדקו ב־36 השעות האחרונות, אך שינוי תנאים מיידי באתר המנפיק עשוי להגיע לפני הריצה הבאה.
