# Couponia Catalog — Stage 5.5: פרסום הטבות מאומתות

## למה נדרש feed נפרד?

רשימות חנויות שמכבדות תו קנייה הן לא קופונים. מבצעים בכרטיסי אשראי ומועדונים דורשים מידע על זכאות, תנאים, תוקף ומלאי. לכן `offers/v1` הוא feed נפרד מ־`v3` ואינו מחליף אף רשומת כרטיס או חנות במאגר הקיים.

## מה נוסף

- `src/publish_offers.py` מייצר `dist/offers/v1/{manifest.json,offers.json}` מקבצים שנבדקו מראש בלבד.
- `src/compare_offers.py` משווה SHA של הצעות, כדי שה־Action יפרסם גם כשמאגר התווים לא השתנה, אך לא יפרסם מחדש רק בגלל שינוי השעה במניפסט.
- `config/approved_offers.json` — רשימה ידנית של הטבות שיש עבורן גם הרשאת הפצה וגם הוכחת מקור.
- `config/offer_rights_grants.json` — אישורים מפורשים לכל מקור. **ברירת המחדל ריקה.**
- כל הטבה חייבת לעבור: קישור HTTPS למנפיק ידוע, מוצר/זכאות, תנאים, תוקף, מלאי זמין, בדיקה ב־36 השעות האחרונות, סטטוס issuer_verified, ומסמך/רישום הרשאת הפצה.
- GitHub Actions מוסיף את feed ההטבות ל־`dist/` ומפרסם אותו יחד עם קטלוג התווים, בלי לשנות את v3.

## פרסום ראשון

1. התקן קודם v3.4 (כולל `src/offer_contract.py` ו־GitHub Actions הקיים); אם הותקן Stage 5.4 של המקורות — הוא כבר משולב בתיקון הזה.
2. חלץ את ZIP המאגר לשורש `couponia-catalog`, בצע בדיקת Diff של `.github/workflows/publish-catalog.yml` ואז Commit/Push.
3. הרץ: `python -m unittest discover -s tests -v` וגם `python -m src.publish_offers --out dist/offers/v1`.
4. ב־GitHub Actions הפעל `Build unified Israeli gift-card catalog`, אמת את ה־Actions ואת שני הקבצים ב־`https://shay-m.github.io/couponia-catalog/offers/v1/`.

**תוצאה צפויה כרגע:** `counts.offers = 0`, כי אין שום אישור הפצה מתועד. חוסר הרשאה לעולם אינו הופך אוטומטית להרשאה בעקבות סריקה, GitHub MIT לפרויקט אחר או הימצאות הנתונים באתר ציבורי.

## כיצד להוסיף הטבה בעתיד

1. קבל מהמנפיק הרשאה מפורשת להפצת **נתוני ההטבה** (לא רק רישיון לקוד סורק). תעד מזהה אישור לא רגיש ופקיעת אישור ב־`offer_rights_grants.json`. אל תפרסם מסמכים פרטיים, פרטי קשר אישיים או סיסמאות ב־GitHub.
2. אמת את דף ההטבה המדויק באתר המנפיק, כולל סטטוס מלאי, תוקף, מוצר כרטיס ותנאי זכאות. הוסף רשומה ל־`approved_offers.json` לפי סכמת השדות ב־`src/publish_offers.py` וב־`tests/test_stage55_offers.py`.
3. הרץ את בדיקות ה־Python ואת המחולל. נתון חסר/לא מורשה/לא טרי — **לא יפורסם**; המערכת מדפיסה דו"ח סיבות השמטה.
4. האפליקציה מציגה הטבה רק אחרי בדיקת SHA256 ותוקף נוספת במכשיר. פקיעת נתון מחייבת בדיקה מחודשת במקור, ולא שינוי אוטומטי של זמן האימות.

## הערות ובדיקות

בארכיון v3.4 הקודם אין את `seed/catalog-v2.db`, ולכן חלק מבדיקות קטלוג התווים המקורי לא יכולות לעבור על בסיס ארכיון העדכון בלבד. זהו תנאי של ה־Repository המלא, **לא** כישלון שנובע משכבת ההטבות החדשה. את הבדיקות החדשות ניתן להריץ בנפרד: `python -m unittest discover -s tests -p 'test_stage55_offers.py' -v`.

בוצע מחקר באתרי MAX, ישראכרט וכאל בתאריך 21.11.2026; לא אומתה הרשאה לייצא נתונים שלהם כ־feed ציבורי, ולכן אין כאן העתקת הצעות או סריקה אוטומטית.
